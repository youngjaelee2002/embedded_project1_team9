# Arduino 1 — 최신 2·3·4번 통합 스케치

대상: UNO R3 / ATmega328P / 16MHz. 수업용 SG90·KY-008 모의 동작 프로젝트.
이 폴더 전체를 복사한 뒤 `arduino1_communication.ino`를 연다.
사용자가 승인한 시연 기본값 **R=200mm, T=4초**가 적용되어 있다.
`SCANNER_PROFILE_CONFIRMED`, `AUTO_PARAMETERS_CONFIRMED`, `TURRET_WORLD_FRAME_CONFIRMED`는 모두 1이다.
예전의 원점 이동 상수 TURRET_ORIGIN_X_MM/Y_MM는 사용하지 않는다.

## 연결

| 1번 핀 | 연결 대상 | 규격 |
|---|---|---|
| D0 RX | 2번 D3 TX | 하드웨어 Serial UART 9600bps |
| D1 TX | 2번 D2 RX | 하드웨어 Serial UART 9600bps |
| D10 SS | 3번 D9 CS | SPI Mode0 / 125kHz / MSB first |
| D11 MOSI / D12 MISO / D13 SCK | 3번 동일 핀 | 48바이트 한 CS 구간 |
| A4 SDA / A5 SCL | 4번 동일 핀 | I2C 0x20 / 100kHz |
| GND | 모든 보드 GND | 공통 기준 |

3번 자신의 D10은 OUTPUT/HIGH로 유지한다. 1번 SS에 연결하는 3번 핀은 D9다.
이 통합본의 1번 UART는 **D0/D1 하드웨어 Serial**이다. (SoftwareSerial은 송수신 중 인터럽트를 막아 3번 SPI 바이트를 잃는다.)
- 1번에 업로드할 때는 D0 선(2번 D3에서 오는 선)을 잠깐 뺀다.
- Serial에는 2번용 바이너리 프레임만 쓴다. 기본값 `A1_USB_DEBUG 0` (controller_types.h).
- 2번 없이 1번만 시험할 때 `A1_USB_DEBUG`를 1로 바꾸면 9600bps로 아래 디버그 줄을 출력한다.

```text
DBG|A2_CMD|SEARCH_FAST                 # Arduino 2 명령 수신 완료
DBG|SPI_READY|seq=2|mode=2|id=0       # Arduino 3이 가져갈 SPI 응답 준비
DBG|A3|mode=2|state=2|ack=2|id=0|err=0|flags=0x07
```

## 시작 흐름

1. 1번은 부팅 후 4번에 HOME/OFF를 보내고, SPI 첫 응답으로 STOP seq0을 준비한다.
2. 3번에서 Hall 기준을 수동으로 맞추고 5초간 유지한다. 3번이 원점을 잡고 ToF가 준비되면
   1번은 SEARCH_SLOW를 새 seq로 준비한다. 3번이 다음 SPI 전송에서 받아 탐색한다.
3. 2번은 첫 상태 응답을 받으면 현재 UI 모드를 1번에 보낸다. 2번 원본의 초기 UI 모드는 AUTO이다.
   따라서 정상 연결·원점 보정·유효 표적·4번 조준 확인이 끝나면 자동 모의 동작이 가능하다.
4. 별도의 UI 스캐너 요청이 없으면 3번은 기존 기본값 SEARCH_SLOW로 전체 탐색한다.
   UI에서 STOP/SLOW/FAST/TRACK/REHOME을 선택하면 1번은 새 command seq로 해당 요청을 준비한다.
5. UI 비상 STOP은 4번 HOME/OFF와 승인을 해제하고 3번에도 STOP/IDLE을 요청한다.
   재개 후에는 UI 스캐너 메뉴에서 필요한 탐색 모드를 다시 선택한다.

1번을 재시작하며 보낸 STOP이 움직이던 3번에 적용되면 3번 원점이 무효화될 수 있다.
이 경우 3번도 재시작하여 초기 원점 보정을 다시 수행한다.
원점 무효·센서 오류 때 1번이 자동으로 REHOME이나 ToF 재초기화를 명령하지는 않는다.

## 좌표 흐름: 3번 → 1번 → 4번

| 구간 | 원점과 각도 | 단위 |
|---|---|---|
| 3번 Cartesian 기본값 | 세계좌표 (500,500)이 센서 축, +x 동 / +y 북 | x,y mm |
| 3번 cylindrical 선택값 | 센서 축 원점, 동0° / 반시계 + | r mm, theta 0.01° |
| 1번 내부 | 센서 축 원점, 북0° / 반시계 + | r mm, theta 0.01° |
| 새 4번 AIM | 센서 축 원점, 북0° / 반시계 + | r mm, theta 0.1°, z=0mm |

직교 입력은 (x−500,y−500)에서 r, theta, vr, vt를 계산한다.
원기둥 입력은 theta_north=(theta_east+27000)%36000으로 기준만 바꾼다.
4번으로 보낼 때는 **r을 그대로 쓰고 theta를 (theta_cdeg+5)/10으로 반올림한 뒤 3600으로 나눈 나머지**를 쓴다.
359.99°는 0.0°로 순환한다. z는 0이다. 표적의 (x,y)를 다시 r/theta로 역변환하지 않는다.

예: 3번 Cartesian (500,800) 또는 cylindrical (300,9000)은
1번 내부 (r=300,theta=0), 4번 두 포탑 AIM `01 2C 01 00 00 00 00`으로 이어진다.
3번의 실물 각도 기준은 원본 코드의 동0°에, 4번 방위각은 북0°에 맞춰 설치해야 한다.

4번 배치는 받은 CFG를 그대로 반영했다.
A=(r=360.6mm, theta=123.7°), B=(360.6mm,236.3°), dir=+1, trim=0, 서보 범위 20~160°.
두 포탑 모두 서보90°가 센서 축을 바라본다. 포탑과 표적 거리가 50mm 미만이면 그 포탑을 제외한다.
실물 배치/장착 보정을 바꾸면 **4번 CFG와 1번 turret4_protocol.h의 CFG를 함께 수정**한다.

## 자동·수동 판단

- 자동: 현재 r≤200mm인 표적은 진입 시간 0초 후보.
- 바깥쪽 표적은 유효한 속도로 (vr²+vt²)t²+2r·vr·t+(r²−R²)=0의 최초 미래 접촉 시간을 계산한다.
- 0<t≤4초인 후보 중 가장 빠른 표적을 선택한다. 동점이면 현재 표적을 유지한다.
- 예측은 직교 속도 벡터가 일정하다는 가정이다. vt는 접선 속도(mm/s)이며 각속도가 아니다.
- 속도를 모르면 현재 거리만 판단한다. r>R인 표적에 대해 도달 시간을 임의로 만들지 않는다.
- 수동: 가장 가까운 유효 표적을 선택한다. 모드·표적·4번 조준 상태가 맞을 때 FIRE 승인을 소비한다.
- 도달 가능한 포탑을 선택하며, 두 포탑 모두 가능하면 같은 표적을 두 포탑이 조준한다.
- 4번의 최근 조준 플래그와 서보 각도·방위각을 확인하고, STOP/오류/표적 유효 시간을 검사한 후 모의 동작.
- 선택이 유지되는 동안 1회만 발행한다. 표적 상실·교체·정지 시 래치가 초기화된다.

## 통신과 상태

2→1 UART: `[02 CMD 03]`.
AUTO=10 / MANUAL=11 / FIRE=20 / 스캐너 STOP=30 / SLOW=31 / FAST=32 /
TRACK=33 / REHOME=34 / 시스템 STOP=FF (모두 16진수).
1→2 UART: `[02 ID rL rH thetaL thetaH 03]`. r은 mm, theta는 0.01도이며 little-endian이다.
표적이 없으면 ID/r/theta를 모두 0으로 보낸다.
일반 상태는 500ms마다 전송하고 변화가 있으면 빠르게 보낸다. 2번 링크 timeout은 1.5초이다.
2번은 heartbeat를 보내지 않으므로 1번은 2번의 무입력만으로 단선을 판정할 수 없다.

3번은 약100ms마다 전체 스냅샷을 보낸다. ISR은 바이트 저장/미리 준비된 응답 출력만 수행한다.
SS HIGH 프레임 종료 확정은 메인 루프에서 한다.
CRC·좌표 변환은 메인에서 처리한다.

4번: AIM_BOTH=7바이트, AIM_ONE=8바이트, HOME=1바이트, LASER=3바이트.
상태는 8바이트이며 마지막 바이트는 앞7바이트 XOR이다. 20ms 주기로 읽는다.
조준 플래그와 서보 목표각±2°, 현재 서보에 대응하는 방위각을 함께 대조한다.
AIM 송신 뒤 최소40ms가 지나고 서로 다른 시각의 정상 응답2개를 확인해야 준비 완료로 본다.
4번 상태에는 표적 ID/명령 번호/물리 각도 센서 값이 없으므로 실제 실행 ACK나 엔코더 피드백은 아니다.

## 남은 프로토콜 제한

**3번에는 표적별 측정 timestamp/관측 번호가 없다.** 전송 seq가 바뀌어도 새 측정이라는 뜻이 아니다.
1번은 12바이트 표적 레코드의 변화 시각을 기록하고 동일 레코드로 1000ms 유효 시간을 연장하지 않는다.
age>0 또는 STALE 표적은 제외한다. SPI 연결 유효 시간 2000ms와 표적 유효 시간은 별개이다.
완전히 같은 새 관측과 재전송을 구분할 수 없어 정지 표적도 만료될 수 있다.
저속 스캔은 한 회전에 약2초 이상이므로 선택이 끊길 수도 있다. 정확한 연속 추적에는 3번 규격 확장이 필요하다.

4번의 firing 비트는 순간 레이저 ON/OFF이다. 3회 점멸 전체의 진행/완료 번호는 없다.
통신 실패 때 같은 FIRE를 자동 재전송하지 않는다. 4번 자체의 명령 링크 watchdog도 없다.

## 코드 읽는 순서

1. controller_types.h: 내부 데이터 구조.
2. arduino1_communication.ino: UART/SPI/I2C 및 controller_loop_once 처리 순서.
3. controller_logic.h: 모드·표적 선택·조준·모의 동작·상태 보고.
4. scanner_protocol.h / scanner_session.h: 실제3번 프레임과 탐색 시작/관측 시각 관리.
5. auto_policy.h: 자동 모드 수식.
6. turret4_protocol.h: 새4번 패킷, 배치, 범위/조준 검증.

전체 검증 결과는 상위 `검증결과.md`에 있다. 가상 통합 시험과 UNO 컴파일을 통과했으며 실물 업로드는 하지 않았다.
