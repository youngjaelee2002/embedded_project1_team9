# RadarWire v1 — SPI Protocol Integration Handoff (UNO 1 / UNO 3)

**Audience:** UNO 1 central-hub team and any other developer implementing an SPI peer for UNO 3.  
**Purpose:** Short, implementation-independent specification of what **must match on the wire**, what teams may implement differently, and what behavior was added to the initial project outline.  
**Status:** Describes the *current supplied firmware*, **not a physically verified two-board integration**. For full details, byte examples, troubleshooting and test plan, use [`SPI_PROTOCOL.md`](SPI_PROTOCOL.md). The two documents describe the same **RadarWire v1 (`0x01`)** protocol; this handoff does not create a different protocol version.

## 1. Bottom line: interoperability, not identical source code

**UNO 1 is free to use completely different functions, structs, libraries, task scheduling and UART/I²C architecture.** The supplied `UNO1_SPI_Hub_Reference.ino` is an **example of the SPI slave** plus an *illustrative* UNO 2 UART bridge; it is **not** a required UNO 1 implementation and is **not** the final hub firmware. The UART bridge, `CMD|...` strings, `RAD|...` / `OBJ|...` reporting, and UNO 4 I²C integration are **outside this SPI contract**.

**CRC correctness alone does not establish compatibility.** Both boards must agree on the byte-for-byte frame format, CRC coverage/parameters, little-endian values, SPI settings, command interpretation, coordinate encoding flag, and sequencing rules below.

| Category | Required for compatible UNO 1 implementation? | May UNO 1 implement it differently? |
|---|---|---|
| SPI slave role, pins, SPI mode/bit order, full 48-byte transfer | **Yes** | Internal ISR/buffer strategy **yes**; on-wire behavior **no** |
| Frame offsets, headers, field sizes, little-endian signedness | **Yes** | Decoder implementation **yes** |
| CRC-8/ATM over bytes 0–46; CRC at byte 47 | **Yes** | CRC function/table implementation **yes** |
| MISO command mode, flags, target, reserved-byte semantics | **Yes** | Where commands originate within UNO 1 **yes** |
| New-command sequence semantics; telemetry ACK field | **Yes** | Internal command-state organization **yes** |
| Cartesian/cylindrical layout indicated by telemetry bit 5 | **Yes** for correct object decoding | UNO 1 may ignore unused object fields or opt not to display them |
| `RadarProtocol.h` helpers and C/C++ structs | **No** | **Yes — optional convenience only** |
| Sample UNO 1 UART bridge to UNO 2 | **No** | **Yes — entirely UNO 1 team responsibility** |
| Specific SPI slave interrupt routines from reference sketch | **No** | **Yes — as long as no bytes are lost and first MISO byte is ready** |
| UNO 1's UNO 4 I²C functions and scheduler | **No** | **Yes — must not disrupt SPI reception** |

## 2. Mandatory electrical and transaction structure

```text
UNO 3 — SPI MASTER                     UNO 1 — SPI SLAVE
D9  (software CS, active LOW) -------> D10 (hardware SS input)
D11 (MOSI) --------------------------> D11 (MOSI)
D12 (MISO) <-------------------------- D12 (MISO)
D13 (SCK) ---------------------------> D13 (SCK)
GND --------------------------------- GND
UNO 3 D10 = OUTPUT / HIGH; it is NOT wired to UNO 1.
```

| Parameter | RadarWire v1 implementation |
|---|---|
| SPI mode | **0** (`CPOL=0`, `CPHA=0`) |
| Bit order | **MSB first** within each byte |
| SCK | **125 kHz**, generated by UNO 3 |
| Frame | **48 full-duplex bytes** under **one continuous CS LOW**; CS returns HIGH afterward |
| CS-to-first-clock setup | UNO 3 currently allows **120 µs** for slave to preload first output byte |
| Inter-byte spacing | UNO 3 currently inserts **100 µs** after each byte; UNO 1 must still handle the transfers correctly |
| Poll cadence | About **100 ms** between transaction starts (subject to scanner-loop timing) |
| Logical initiator | **Always UNO 3**. UNO 1 stages a response in advance; it cannot clock or initiate SPI transfers. |

These specific setup/gap/cadence values are **current UNO 3 implementation settings**, not inherent ATmega328P or SPI standards. UNO 1 must work with the current master's timing; changing these values requires cross-team timing verification. In the SPI slave, prepare MISO byte 0 **before** the first clock edge and subsequent bytes fast enough for the next transfer. Detect CS boundaries, reject incomplete frames, and keep any long UART/I²C activity from breaking the SPI service.

## 3. Mandatory common frame rules

- **Size:** 48 unsigned 8-bit bytes, byte offsets **0–47**.
- **Byte 0:** `0xA5` sync; **byte 1:** `0x01` protocol version; **byte 2:** an 8-bit sequence counter for the direction being transmitted.
- **Byte 47:** **CRC-8/ATM of bytes 0 through 46 inclusive**. Polynomial `0x07`, init `0x00`, non-reflected input/output, XOR-out `0x00`. Verification vector: ASCII `123456789` → `0xF4`.
- **16-bit integers:** little-endian (low byte then high byte); signed fields use two's complement. **MSB-first SPI bit order does not alter byte endianness**.
- Reject received frames with incorrect length, sync, version or CRC. Do not interpret an invalid command as a new action; do not publish corrupted telemetry as valid positions.
- **All reserved MISO command bytes 6–46 must be zero.** The current UNO 3 implementation rejects nonzero reserved command bytes even when their CRC is correct.

Minimal portable CRC function (equivalent source is acceptable):

```c
#include <stdint.h>
uint8_t radar_crc8(const uint8_t *bytes, uint8_t length) {
    uint8_t crc = 0;
    for (uint8_t i = 0; i < length; ++i) {
        crc ^= bytes[i];
        for (uint8_t b = 0; b < 8; ++b)
            crc = (crc & 0x80) ? (uint8_t)((crc << 1) ^ 0x07)
                               : (uint8_t)(crc << 1);
    }
    return crc;
}
/* tx[47] = radar_crc8(tx, 47); */
```

## 4. Exact 48-byte packet layouts

### A. UNO 3 → UNO 1, MOSI: scanner telemetry

| Byte offset | Field | Required interpretation |
|---|---|---|
| `0` | Sync | `0xA5` |
| `1` | Version | `0x01` |
| `2` | `telemetry_seq` | Incremented for each initiated frame; wraps `255 → 0` |
| `3` | `active_mode` | `0 STOP`, `1 SEARCH_SLOW`, `2 SEARCH_FAST`, `3 TRACK_TARGET` |
| `4` | `status_flags` | See bit definitions below; **bit 5 chooses object format** |
| `5` | `object_count` | `0..3`; only first `count` records are populated |
| `6–17` | `object[0]` | 12-byte object record |
| `18–29` | `object[1]` | 12-byte object record |
| `30–41` | `object[2]` | 12-byte object record |
| `42` | `scanner_state` | `0 CALIBRATION`, `1 IDLE`, `2 MOVING`, `3 FAULT` |
| `43` | `hall_strikes` | Consecutive missed Hall-reference checks |
| `44` | `selected_target_id` | Current selected/priority target; zero means round-robin/all |
| `45` | `accepted_cmd_seq` | Most recently accepted MISO command sequence; initial `0xFF` |
| `46` | `last_error` | See `SPI_PROTOCOL.md` for error enumeration |
| `47` | CRC | CRC-8/ATM of bytes `0..46` |

**Telemetry status bitfield (byte 4):**

| Mask | Meaning if set |
|---|---|
| `0x01` | Hall home valid |
| `0x02` | ToF ready |
| `0x04` | Motor driver commanded HOLD (not measured torque) |
| `0x08` | Hall sensor active |
| `0x10` | Rehome pending |
| **`0x20`** | **Cylindrical object records**; if clear, records are **Cartesian** |
| `0x40` | Target lost |
| `0x80` | SPI command-link timeout |

**One object occupies 12 bytes**, at `base = 6 + 12 × slot_index`:

| Relative offset | Cartesian if bit `0x20` clear | Cylindrical if bit `0x20` set |
|---|---|---|
| `+0` | `id : u8` | `id : u8` |
| `+1` | `object_flags : u8` | `object_flags : u8` |
| `+2..3` | `x_mm : i16 LE` | `r_mm : u16 LE` |
| `+4..5` | `y_mm : i16 LE` | `theta_cdeg : u16 LE` |
| `+6..7` | `vx_mm_s : i16 LE` | `vr_mm_s : i16 LE` |
| `+8..9` | `vy_mm_s : i16 LE` | `vt_mm_s : i16 LE` |
| `+10` | `quality : u8` | `quality : u8` |
| `+11` | `age_scans : u8` | `age_scans : u8` |

`object_flags` bit 0 = velocity valid, bit 1 = inside board, bit 2 = stale/aged; bits 3–7 reserved. `id=0` denotes empty slot. Do not infer velocity validity from a zero numeric value. `theta_cdeg` is **centidegrees** (e.g., 9000 = 90.00°); `vt_mm_s` is **tangential linear speed in mm/s**, **not** angular degrees/s. Cylindrical origin is scanner axis `(500,500) mm`, zero angle at world +X, positive counterclockwise. Objects may be stale yet remain in a snapshot until their IDs expire. Values are quantized; converting layouts can introduce rounding.

**Only ONE of the two layouts is present in a given SPI frame**, not both. UNO 3 chooses its outgoing layout with `SPI_COORDINATE_MODE` at compile time. The UNO 3 **USB monitoring GUI displays both** by using the scanner's separate read-only serial telemetry. UNO 1 should select its decoder based on byte 4 bit `0x20`, so no UNO 1 reflash is needed when UNO 3 changes formats.

### B. UNO 1 → UNO 3, MISO: staged hub command

| Byte offset | Field | Required value/behavior |
|---|---|---|
| `0` | Sync | `0xA5` |
| `1` | Version | `0x01` |
| `2` | `command_seq` | Increment modulo 256 for each **new command**; maintain identical sequence for periodic repeated frames |
| `3` | `requested_mode` | `0 STOP`, `1 SEARCH_SLOW`, `2 SEARCH_FAST`, `3 TRACK_TARGET`, `4 REHOME` |
| `4` | `command_flags` | `0x01` requests ToF retry/reinitialization when **not moving**; all other bits zero |
| `5` | `selected_target_id` | `0 = all/round-robin`; `1..255 = specific target ID` |
| `6–46` | Reserved | **41 zero bytes**; nonzero is rejected |
| `47` | CRC | CRC-8/ATM of bytes `0..46` |

**Example initial STOP command, 48 hex bytes** (`seq 0`, `target 0`, CRC `0x23`):

```text
a5 01 00 00 00 00 00 00 00 00 00 00 00 00 00 00
00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 23
```

## 5. Command sequencing and operation: essential for matching firmware

1. **At startup**, UNO 1 stages `STOP, target 0, command_seq 0`, with a valid CRC, **before** UNO 3 clocks its first frame.
2. Each ~100 ms exchange transfers **old/prepared MISO command** and **current MOSI telemetry simultaneously**. UNO 3 applies a valid command **after** the exchange; changed scanner state or ACK is seen in a **later** telemetry frame, never retroactively in the same snapshot.
3. UNO 3 validates header, version, CRC, mode, allowed flag bits, and zero-reserved bytes. Malformed commands are rejected and must not cause actions.
4. A **new command sequence** triggers processing. Receiving the same accepted `command_seq` again is a **duplicate**: it refreshes link liveness but does **not** repeat side effects (e.g. manual REHOME). UNO 1 should increment seq for *every intentional new request*, even when requesting the same mode again.
5. UNO 3 reports the last accepted `command_seq` in telemetry byte **45**. This is **acceptance/dispatch**, **not proof of movement, successful homing, or command completion**. Consult active mode, state, flags and error to learn outcome. `0xFF` starts as the uninitialized ACK sentinel but is also a valid sequence after wrapping.
6. `requested_mode=4` initiates **manual Hall calibration**. Only calibration commands FREE torque; after five seconds of steady Hall detection the scanner automatically commands HOLD. Other modes, including STOP/IDLE, retain HOLD. **There are no HOLD/FREE SPI commands.** Automatic resumption after REHOME follows scanner local-state policy.
7. Scanner timeout policy in the supplied firmware is **3 seconds since the last CRC-valid hub command** after first link establishment. If the link times out during movement, UNO 3 stops and requires re-calibration before further scanning. A later duplicate frame may restore liveness but does not reissue a stopped mode; send a **new sequence** once it is safe.

**Important nuance:** UNO 3 currently refreshes link liveness on a *header- and CRC-valid* command even if the command is subsequently rejected due to invalid mode/flags/reserved bytes. Do not confuse link-alive with command-accepted. This is a current firmware behavior, not an instruction to send invalid frames as keepalives.

## 6. What changed or was fixed beyond the original outline?

The outline provided the general topology and proposed 48-byte transfer and object slots, but did not fully specify every behavior. **The following are additional choices made by the current implementation**; compatible UNO 1 firmware should match their resulting wire semantics:

| Decision added/finalized | Effect on UNO 1 team |
|---|---|
| CRC-8/ATM parameters finalized | **Must use same CRC**, not merely any CRC-8 |
| Telemetry byte 4 bit `0x20` coordinate identifier | **Must decode objects according to that bit** when consuming positions |
| Telemetry bytes `42..46` assigned to state, Hall strikes, selected ID, ACK, error | **Must preserve byte positions**; fields may be ignored if application has no use for them |
| Command flag bit 0 assigned to ToF retry; STOP uses `requested_mode=0` | **Must use current command encoding**, not the provisional stop-bit idea |
| Command sequencing and duplicate handling | **Must increment sequence on new commands** and stage stable command buffers |
| 3-second command-link timeout; stop/rehome recovery | UNO 1 should transmit valid command frames regularly; **UNO 3 enforces safety policy locally** |
| 125 kHz clock, 120 µs setup, 100 µs inter-byte spacing, ~100 ms polling | **Master implementation settings**; UNO 1 must reliably receive/respond with its combined UART/I²C load |
| Torque automatically FREE during calibration, HOLD otherwise | **Scanner internal motor policy**; UNO 1 supplies only mode/target requests |
| `vt_mm_s` name and units (tangential speed) | **Use mm/s**, not angular speed, when decoding cylindrical records |

The **3-second duration**, choice to invalidate home after link loss, ToF retry flag, status expansions and timing margins are implementation-specific decisions rather than original-outline requirements. They can be reconsidered **as a coordinated firmware/protocol change**; they must not silently diverge between independently built boards. Any change to versioned layout, numeric units, offsets or semantics should use a new version and matching integration tests.

## 7. Minimal UNO 1 integration checklist

- [ ] Configure D10 as SPI slave SS **input**, D12 as MISO **output**; connect common GND and the four SPI signals exactly as specified.
- [ ] Configure mode 0 / MSB-first; receive **exactly 48 bytes** while CS stays LOW and preload first MISO byte before SCK begins.
- [ ] Build complete MISO command buffer *off-line*; set header/sequence/mode/flags/target; zero bytes 6–46; compute CRC into byte 47. **Never let the ISR transmit a partially edited buffer.**
- [ ] On receipt of complete MOSI frame, validate header/version/CRC and `object_count <= 3`; decode the chosen 12-byte slot based on `status_flags & 0x20`; track telemetry sequence and ACK when relevant.
- [ ] Start with a valid STOP seq 0 command; increment seq for real changes, not every polling exchange. Check acknowledgment in a **later** telemetry frame.
- [ ] Keep SPI ISR/driver responsive while UNO 1 also uses UART and I²C; reject incomplete CS frames; test with a logic analyzer and worst-case interrupt traffic.
- [ ] Exercise both coordinate modes, STOP/SLOW/FAST/TRACK/REHOME, malformed CRC/header/reserved bytes, duplicate sequences, target loss and SPI link interruption.
- [ ] Treat the reference UART bridge as **optional**, not as a required interface to UNO 2. The PC USB GUI attaches separately to UNO 3 and is **read-only**.

**Acceptance criterion:** An independently written UNO 1 program that transmits the correct 48-byte MISO commands, correctly receives/validates the 48-byte MOSI telemetry and observes the framing, timing and sequencing rules is compatible even if it shares **zero C++ structs or functions** with this project.

**Not yet established:** Final AVR builds on both boards, physical SPI signal integrity/ISR timing, cross-team UNO 1 UART/I²C scheduling and system-level motor/ToF performance. Do not treat host-side syntax/unit tests as bench verification.
